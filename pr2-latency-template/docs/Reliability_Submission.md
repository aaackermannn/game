ПР №2 вошла в `master` форка GitVerse коммитом слияния `2d86740`. Подготовленная для этого форка ветка `feature/reliable-delivery` использует данный коммит как базу, поэтому Pull Request в `master` показывает изменения ПР №3. [Сведения о сдаче ПР №2](Submission_Checklist.md).

## Описание Pull Request

### ПР №3 Надёжная доставка выстрелов в Loop

Этот PR расширяет UDP-стенд ПР №2. Клиент отмечает доставку `SHOOT` при получении `ACK`, повторяет команду по адаптивному RTO и завершает ожидание при исчерпании пяти попыток. Выделенный сервер подтверждает повтор с тем же номером без повторной обработки. `MOVEMENT`, `PING` и `PONG` передаются без подтверждений.

Проверка из чистой копии под Windows x64 и MSVC Release прошла по всем трём группам CTest. В шести сериях по 100 команд сервер обработал каждый выстрел один раз. Клиент подтвердил 600 команд и сделал в сумме 48 повторных отправок. Сценарий исчерпания попыток проверен отдельно при полном отсутствии ACK.

## Задачи для трекера

| Заголовок | Что проверить при приёмке |
|---|---|
| Версия 2 протокола UDP и подтверждение ACK | Заголовок содержит `requiresAck`. Датаграмма ACK содержит номер подтверждаемой команды. Парсер отклоняет неверную версию, тип, размер, флаг и несовпадающие номера. |
| Менеджер повторных передач SHOOT | Менеджер работает без сокетов. Запланированный повтор сохраняет байты и номер команды. Повторный ACK игнорируется. После пятой попытки и полного RTO фиксируется `failed`. |
| Адаптивный RTO из измерений RTT | Корректные PONG и ACK первой попытки обновляют SRTT и RTTVAR. ACK после повтора завершает доставку без замера RTT. RTO остаётся в диапазоне 100–3000 мс. |
| Интеграция клиента и выделенного сервера | Клиент снимает команду с ожидания по ACK. Сервер подтверждает дубли и применяет каждую команду один раз. Два клиента могут использовать одинаковый номер. |
| Автоматические проверки доставки | Catch2 проверяет двоичный формат, границы окна, дубли ACK и исчерпание попыток. UDP-тесты проверяют ответы сервера и завершение клиента при полном отсутствии ACK. |
| Эксперимент и материалы защиты | В CSV есть шесть серий по 100 уникальных команд. Таблица и два графика согласуются с измерениями. DOCX объясняет термины и позволяет воспроизвести демонстрацию. |

## Вопросы для ревью

1. Совпадают ли смещения и типы полей со спецификацией? Проверяет ли клиент источник ответа и номер команды?
2. Может ли повторный `SHOOT` дать второй игровой эффект? Проверены ли запоздавшие номера внутри окна и переход через 65535?
3. Исключены ли из расчёта RTO неоднозначные замеры ACK после повтора? Дожидается ли клиент полного RTO после последней отправки?
4. Можно ли по CSV воспроизвести число попыток и время до ACK? Описано ли, на каком направлении эмулировались потери?

Статус внешнего ревью подтверждается обсуждением в Pull Request. Для индивидуальной сдачи формат приёмки согласовывается с преподавателем, как в ПР №2.
